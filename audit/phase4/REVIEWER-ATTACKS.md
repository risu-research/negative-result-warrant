# Reviewer attacks and exact responses

## 1. “Query completeness already solved this.”

- Reviewer formulation: Database and Semantic Web research has long formalized when incomplete data supports negation. Renaming query completeness as a Negative Result Warrant is not a contribution.
- Disposition: **NARROW**.
- Exact response: Correct for the semantic atom. Project 4 does not claim a new logic of absence. Its surviving claim is a real executable profile that acquires provider-native scope/exactness evidence, binds it to one operation-derived proposition, transports it through MCP, and revalidates it at use.
- Claim language changed: Replace “new negative-evidence principle” with “executable Algolia negative-evidence profile.”

## 2. “CROWN-QA already has `Certified-Negative` versus `Unknown` and certificates.”

- Reviewer formulation: CROWN-QA isolates query-relative coverage, uses `Certified-Negative`/`Unknown`, and elicits structured certificates. Project 4 duplicates its central distinction.
- Disposition: **NARROW**.
- Exact response: Correct for C1 and the coverage-sensitive label distinction. CROWN-QA is an LLM benchmark whose certificate fields are model-produced diagnostic outputs. Phase 3 instead evaluates exact captured provider bytes deterministically and carries the resulting private evidence object to a downstream operation. The terms `Certified-Negative` and “certificate” are avoided.
- Claim language changed: Use `WARRANTED_ZERO` and “bounded observation-relative warrant,” never “certified negative” or “certified absence.”

## 3. “PCAA already carries evidence and assumptions into pre-action admissibility.”

- Reviewer formulation: Proof-Carrying Agent Actions already defines a portable action certificate, pre-action admissibility, assumption capture, receipts, replay, and runtime neutrality. Project 4 is a smaller PCAA instance.
- Disposition: **NARROW**.
- Exact response: PCAA subsumes the broad action-governance framing and must receive credit for it. It does not define negative-query completeness, provider-native sufficiency, proposition-preserving evidence acquisition, or this exact real-source/MCP/receiver chain. Project 4 therefore claims an executable premise profile, not a proof-carrying agent action architecture.
- Claim language changed: Remove “proof-carrying action,” “runtime governance,” and broad “portable action certificate”; say “negative premise admissible to one operation.”

## 4. “Proof-carrying authorization already does the whole abstract pattern.”

- Reviewer formulation: PCA gives a server an exact challenge, lets a client iteratively fetch missing facts, checks the proof at the receiver, and grants access only on success. Add database completeness as an application-specific predicate and Project 4 follows.
- Disposition: **NARROW**.
- Exact response: This is the most damaging combination argument and defeats atomic novelty for C3, C4, C5, C7, and C8. The remaining contribution is implementation evidence: a concrete provider-grounded negative-query profile with exact byte/authority/source bindings and a real MCP hop. It is a reusable executable profile, not a new proof-carrying paradigm.
- Claim language changed: Lead with “executable Algolia profile” and explicitly state that exact binding, iterative evidence acquisition, and receiver checking are prior art.

## 5. “PCN already has claim-bound, external, fail-closed verification.”

- Reviewer formulation: Proof-Carrying Numbers already binds output tokens to structured claims and lets an external renderer refuse unverified claims. `BoundNegativeEvidence` is the same pattern for zero.
- Disposition: **NARROW**.
- Exact response: The binding and fail-closed verifier pattern are prior art. PCN verifies numeric presentation under a declared policy; it does not acquire query-relative coverage from a source, distinguish ordinary from evidence-strengthened observations, or gate an operational premise after MCP transport.
- Claim language changed: Do not claim claim-binding or fail-closed checking as new; claim only their provider-grounded negative-query composition.

## 6. “ProvenanceGuard already verifies MCP claims against their source.”

- Reviewer formulation: ProvenanceGuard consumes MCP traces, assigns claims to stable source IDs, verifies support, and emits allow/block decisions. Project 4 is another source-aware MCP verifier.
- Disposition: **NARROW**.
- Exact response: Source-aware MCP verification is prior art. ProvenanceGuard performs post-hoc natural-language claim attribution using NLI, alignment, and calibration. Phase 3 performs deterministic structural validation of a provider-specific negative observation before a local effect and requires an exact operation-derived proposition. The overlap forbids any broad “MCP provenance guard” claim.
- Claim language changed: Say “private evidence envelope carried by MCP,” not “MCP provenance verification.”

## 7. “in-toto already binds evidence to exact subjects.”

- Reviewer formulation: Digest-bound subjects and typed predicates are standard attestation machinery, so exact source/claim binding is not new.
- Disposition: **ACCEPT**.
- Exact response: Agreed. Project 4 does not claim subject binding. Its local hashes and proposition identities instantiate that established pattern without adding signatures, issuer verification, or transparency.
- Claim language changed: List exact binding under assumed prior art; avoid “new subject-bound evidence primitive.”

## 8. “Q was not epistemically insufficient; your profile manufactured `UNKNOWN`.”

- Reviewer formulation: Q directly addressed `bestbuy`, set `enableABTest=false`, returned zero and exhaustive hit counts. Algolia’s documentation says `indexUsed` matters when A/B routing may change the index. Requiring the echo after disabling A/B is a deliberately stricter experimental rule, not an Algolia necessity.
- Disposition: **ACCEPT**.
- Exact response: Correct. The experiment supports only this statement: under the experimental no-inference profile, Q lacked an explicit source-reported effective-index witness and Q′ acquired it. It does not show that Algolia generally requires `getRankingInfo` before a zero result is knowable.
- Claim language changed: Replace “Q was epistemically insufficient” with “Q lacked the explicit effective-scope witness required by the experimental profile.”

## 9. “One public demo provider cannot support a portable or general claim.”

- Reviewer formulation: A single nonce query against one mutable public Algolia demo application establishes no cross-provider or even broad Algolia generality.
- Disposition: **ACCEPT**.
- Exact response: Correct. Phase 3 is an existence demonstration for one application, index, query, credential view, profile, and observation pair. Portability remains an architectural hypothesis supported by frozen synthetic profiles, not a real-source empirical result.
- Claim language changed: Use “one real Algolia vertical slice” and “can exist”; remove “APIs,” “provider-independent,” and “general.”

## 10. “The source can change between observation and effect.”

- Reviewer formulation: The zero result is time-bound. Without a transaction, version token, lock, or recheck, the operation can act after a matching record appears.
- Disposition: **ACCEPT**.
- Exact response: Correct. The warrant makes a bound observation admissible as a premise; it does not establish state continuity. Phase 3 does not solve freshness or TOCTOU and must not call the downstream effect safe.
- Claim language changed: Add “observation-relative” and “no state-continuity guarantee”; avoid “safe action” and “valid at commit.”

## 11. “The system trusts the issuer and the source’s truth.”

- Reviewer formulation: Hashes show consistency, not truth. Algolia did not sign the warrant; a compromised endpoint, credential view, adapter, or profile can produce a perfectly bound false claim.
- Disposition: **ACCEPT**.
- Exact response: Correct. Receiver validation establishes structural, byte-binding, source-instance, authority-fingerprint, and proposition consistency under local trust policy. It does not independently attest Algolia’s database contents, completeness beyond documented response fields, or server honesty.
- Claim language changed: Use “source-reported” and “under the profile’s trust assumptions”; avoid “truth certificate,” “proof of absence,” and “trusted source” without qualification.

## 12. “MCP is merely a carrier.”

- Reviewer formulation: Private `_meta` data surviving one SDK path says nothing about MCP semantics or interoperability. MCP does not define `WARRANTED_ZERO`.
- Disposition: **ACCEPT**.
- Exact response: Correct. MCP contributes a real serialization and transport boundary plus schema/validation affordances. All completeness semantics, evidence branding, and receiver trust are Project 4 application logic.
- Claim language changed: Say “transported through MCP” or “MCP carriage,” never “MCP guarantee,” “MCP warrant,” or “standard MCP property.”

## 13. “The action is a toy local effect, not production safety.”

- Reviewer formulation: Incrementing an in-memory counter after a deterministic guard does not establish safe autonomous action, durable exactly-once effects, rollback, authorization, or operational risk reduction.
- Disposition: **ACCEPT**.
- Exact response: Correct. The effect demonstrates only that the local operation derives its required proposition, blocks without exact evidence, and executes once with accepted evidence. It is an executable gate test, not a production agent-safety result.
- Claim language changed: Use “deterministic local operation” and “effect count 0→1”; avoid “safe agent action,” “production-ready,” and “exactly once” outside this process.

## Strongest attack and response

Strongest attack: **“Database query completeness supplies the negative semantics, while proof-carrying authorization supplies exact challenge binding, iterative evidence acquisition, receiver verification, and gated access; Algolia and MCP are incidental adapters.”**

Exact response: **Accept the atomic and combination precedent, then narrow. Project 4 claims no new negative logic or proof-carrying action principle. It contributes a falsifiable executable Algolia profile showing that provider-native scope/exactness evidence can be normalized, bound to an operation-derived bounded negative proposition, carried through MCP, and revalidated at use. Whether that concrete profile is useful is the externalization question.**

## Atomic claim classifications

The labels below apply to the claim atoms, not to the exact Phase 3 codebase.

| ID | Atomic claim | Classification | Basis |
|---|---|---|---|
| C1 | A non-observation remains `UNKNOWN` absent scope/completeness evidence. | PRIOR ART | Open-world and partial-closed-world database theory; CROWN-QA’s `Unknown` versus query-covering negative. |
| C2 | Provider-native evidence can issue a bounded negative warrant. | LIKELY PRIOR ART | Query-completeness metadata and provider exactness/closure fields already support this inference pattern; the Project 4 serialization is implementation-specific. |
| C3 | An ordinary query can be strengthened without changing the proposition to acquire missing evidence. | LIKELY PRIOR ART | PCA iterative proving acquires missing facts; Algolia and Elasticsearch expose request flags that add exactness/scope evidence. The explicit proposition comparator is a composition detail. |
| C4 | A warrant is bound to the exact `ZeroProposition`. | PRIOR ART | Exact challenge/goal binding in PCA, claim-bound tokens in PCN, and digest-bound subjects in in-toto. |
| C5 | Evidence for P1 must not authorize P2. | PRIOR ART | Core proof/claim/subject-binding property across PCA, PCN, authorization, and attestation systems. |
| C6 | A warrant can survive protocol transport without the carrier acquiring completeness semantics. | COMBINATION-ONLY | Typed evidence transport is routine; the useful point is the explicit separation between Project 4 semantics and MCP carriage. |
| C7 | Transported evidence must be receiver-validated. | PRIOR ART | PCC/PCA host checking, PCN renderer checking, attestation verification, and MCP’s client-validation guidance. |
| C8 | An operation derives its required premise from its own inputs and consumes only exact matching evidence. | LIKELY PRIOR ART | Request-scoped authorization and exact challenge checking already enforce this design; the Algolia `ZeroProposition` instance is specific. |
| C9 | The full real chain is observation → `UNKNOWN` → preserving verification → `WARRANTED_ZERO` → proposition binding → MCP → receiver validation → deterministic operation. | DISTINCT ON CURRENT SEARCH | No located primary source instantiates this entire negative-query chain. Distinctness attaches only to the narrow executable composition, not its components. |

## Not novel

The semantics of absence, completeness-relative negation, exact claim binding, proof/evidence transport, receiver-side validation, provenance, fail-closed operation gates, action certificates, provider exactness fields, and deterministic policy decisions are prior art or likely prior art.

## Surviving contribution

The surviving object is an executable Algolia profile and evidence artifact that joins those mechanisms across a real HTTP source, a proposition-preserving evidence-strengthening request, an exact negative premise, an MCP boundary, and a receiver-validated operation. It is publishable only as a narrow composition/executable-profile claim.
